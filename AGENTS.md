## Development

When starting the dev server, use background mode:

```
astro dev --background
```

Manage the background server with `astro dev stop`, `astro dev status`, and `astro dev logs`.

## Database & Auth

Cloudflare D1 (`DB` binding) accessed through Drizzle ORM; auth is better-auth with
Google as the only social provider.

- `src/lib/db/schema.ts` — Drizzle schema (auth tables generated by the better-auth CLI)
- `src/lib/auth.ts` — server auth instance, built lazily because bindings come from `cloudflare:workers`
- `src/lib/auth-client.ts` — browser client
- `src/middleware.ts` — populates `Astro.locals.user` / `Astro.locals.session`
- `migrations/` — D1 SQL migrations

Bindings are read via `import { env } from 'cloudflare:workers'`. `Astro.locals.runtime.env`
was removed in Astro v6 and throws if used.

Routes that need a session must set `export const prerender = false`.

After changing the schema: `npm run db:generate` then `npm run db:migrate:local`.
Secrets live in `.dev.vars` locally (see `.dev.vars.example`) and in Wrangler secrets in production.
