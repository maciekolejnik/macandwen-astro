## Worktrees

Every new feature gets its own git worktree, so parallel sessions never share a
checkout. Branch switches and installs in one tree then can't disturb another.

```sh
git worktree add ../macandwen-astro-<slug> -b <branch> main
cd ../macandwen-astro-<slug>
npm ci
cp ../macandwen-astro/.dev.vars .        # not in git
npm run db:migrate:local                 # each tree gets its own .wrangler state
```

Work only inside that directory for the lifetime of the feature. Never revert or
delete files in a checkout another session is using. Once the branch is merged,
`git worktree remove ../macandwen-astro-<slug>`.

Run `git worktree list` before starting — if the repo root is already on someone
else's feature branch, create a new worktree rather than switching branches.

## Development

Start the dev server in background mode:

```sh
astro dev --background
```

Manage it with `astro dev stop`, `astro dev status`, and `astro dev logs`.

Check work with `npx astro check` (types), `npm test`, and `npm run build` — the
same three steps CI runs.

## Tests

`vitest` with `@cloudflare/vitest-pool-workers`, so tests run inside workerd
against a real D1 database rather than mocks. Files live in `test/`.

```sh
npm test                 # once
npx vitest               # watch
```

`test/helpers.ts` seeds a signed-in user directly, since a real Google sign-in
cannot run in tests. Coverage is the auth layer only — see
`docs/features/authentication.md`.

## Database & Auth

Cloudflare D1 (`DB` binding) accessed through Drizzle ORM; auth is better-auth
with Google as the only social provider. Full detail lives in
`docs/features/database.md` and `docs/features/authentication.md` — read those
before changing the schema or touching the auth flow.

- `src/lib/db/schema.ts` — Drizzle schema (auth tables generated by the better-auth CLI)
- `src/lib/auth.ts` — server auth instance, built lazily because bindings come from `cloudflare:workers`
- `src/lib/auth-client.ts` — browser client
- `src/middleware.ts` — populates `Astro.locals.user` / `Astro.locals.session`
- `migrations/` — D1 SQL migrations

To query the database by hand, pass the *database name* `macandwen`, not the
`DB` binding name — `wrangler d1 execute DB ...` fails with a misleading
"account is not valid or is not authorized" (7403) error:

```sh
npx wrangler d1 execute macandwen --local --command "SELECT * FROM user"
npx wrangler d1 execute macandwen --remote --command "SELECT * FROM user"
```

Bindings are read via `import { env } from 'cloudflare:workers'`.
`Astro.locals.runtime.env` was removed in Astro v6 and throws if used.

Routes that need a session must set `export const prerender = false`; everything
else stays prerendered.

After changing the schema: `npm run db:generate`, then `npm run db:migrate:local`.
Secrets live in `.dev.vars` locally (see `.dev.vars.example`) and in Wrangler
secrets in production.
